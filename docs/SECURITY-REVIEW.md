# 安全审查：局域网扫描功能（v0.2 增量）

审查对象：Android 端 `LanScanner.kt` + 服务器地址输入规范化（自动补全 `http://`）+ 网关新增的未鉴权 `/ident` 端点 + 对 `/health` 的收紧。
结论：**通过**，无高危问题；修复了 1 个低危信息泄露（`/health` 泄露上游 cwd/模型名），
并在本文件中记录了若干经过评估后有意接受的设计取舍。

## 附：v0.2.1 增量审查（本次构建前）

本次完善在构建前又做了四件事，结论：**通过**。

| 项 | 改动 | 结论 |
|---|---|---|
| Token 静态加密 | `ServerConfigStore` 由 DataStore 明文 JSON 改为 **Jetpack security-crypto `EncryptedSharedPreferences`**：MasterKey=AES256_GCM（Android Keystore 硬件保护），key 名 AES256_SIV、值 AES256_GCM | ✓ 手机 root/文件导出后无法直接读明文 token（token=电脑远程执行权限） |
| 关闭云备份 | `AndroidManifest` `android:allowBackup="false"` | ✓ 防止加密后的服务器库（含 token 密文+Keystore 关联材料）被 Google 云备份拖走，离线暴力破解面归零 |
| 网关 413 顺序 | 修复网关请求体超限时先 `destroy()` 再写 413 的问题：现在**先回 413 再断连** | ✓ 客户端得到规范的 413 而非裸连接重置；DoS 防护语义不变 |
| 交互面 | 聊天页新增智能滚动（阅读历史时不强制拉底）、回到底部按钮、IME 发送、会话重命名、后台任务条、排队提示、错误横幅 | 无新增攻击面 |

## 附：手机文件上传端点审查（v0.2.1）

网关新增 `PUT /upload`（手机 → 电脑文件），结论：**通过**。

| 属性 | 实现 | 结论 |
|---|---|---|
| 鉴权 | 与 `/api` 同等的 Bearer token（SHA-256 + timingSafeEqual） | ✓ 无 token 无法上传 |
| 路径穿越 | 文件名清洗（去 `/ \ : * ? " < > |` 与控制字符）、裸 `..` 变 `_`、目录由服务端决定（`<会话cwd>/uploads` 或配置的 `uploadDir`），客户端 `cwd` 参数仅作绝对路径前缀 | ✓ 无法写任意路径 |
| 覆盖与资源 | 重名自动 `-1` 后缀永不覆盖；大小上限 `uploadLimitMB`（默认 512MB）超限 413；流式写盘不占内存 | ✓ |
| 会话工作区对齐 | App 携带 `session.list` 的会话 cwd，文件落在该会话工作区 `uploads/`，代理 fs 工具直接可见 | ✓ 无跨会话目录暴露 |
| 信任边界 | `cwd` 参数受 token 信任保护（拿到 token 本身即等于远程代码执行权限，不新增能力） | 接受 |

**评估后接受的取舍（v0.2.1）**：

- security-crypto 为 `1.1.0-alpha06`（最新 alpha，上游已数年冻结）：API 稳定且被广泛使用；
  Keystore 不可用时（极少数定制 ROM）`EncryptedSharedPreferences` 会抛异常，App 保存服务器时会失败并提示——宁可失败也不回退明文。
- 删除 DataStore 依赖：加密方案由 Keystore 承担，DataStore 无加密能力且此前是明文存储的载体，一并移除减少攻击面。

## 1. 威胁模型

- 攻击面：与手机同一局域网（或能触达网关端口）的任何设备。
- 资产：网关 token（= 电脑上的远程代码执行权限）、PC 文件系统布局信息、DSH 部署信息。
- 信任边界：家庭 WiFi 为边界；公共网络/开放端口不在 v1 安全模型内（见 ARCHITECTURE.md）。

## 2. 扫描流程的安全属性

| 属性 | 实现 | 结论 |
|---|---|---|
| 触发方式 | 仅用户点击「扫描」按钮；无后台定时扫描 | ✓ |
| 网络行为 | 每个候选 IP:port 发 1 个 `GET /ident`；**不携带 token、不携带任何凭据** | ✓ |
| 目标端影响 | `/ident` 为静态 JSON（网关名+版本），无状态变更、无动态计算 | ✓ |
| 识别精确性 | 必须响应 200 且 JSON `gateway.name == "dsh-remote-gateway"` 才认定；不会把任意 HTTP 服务误判为网关 | ✓ |
| 资源边界 | 并发上限 64、连接 300ms/读 500ms/总 900ms 超时、随时可取消 | ✓ |
| 重定向 | OkHttp `followRedirects(false)`：防止探测请求被任意 30x 劫持到其他目标 | ✓ |
| 权限 | 无新增权限（INTERNET/ACCESS_NETWORK_STATE 已声明）；子网信息来自 `LinkProperties`，**不需要位置权限** | ✓ |
| 流量隐私 | 探测的是本地网段地址；对每个 IP 仅一次 GET，与常见设备发现（mDNS/ARP）同量级 | 接受 |
| 失败处理 | 探测异常全部吞掉（预期大多数 IP 不可达），不产生日志/告警刷屏 | ✓ |

## 3. 地址输入规范化（自动补全 http://）的安全属性

| 属性 | 实现 | 结论 |
|---|---|---|
| 补全范围 | 仅当输入匹配「以数字开头或含点号的主机/IP[:端口]」且未携带 `http://`/`https://` 前缀时，才自动补 `http://` | ✓ 不会把手输的 `https://…` 改坏 |
| 双重防线 | 对话框实时补全（`normalizeUrlInput`）+ ViewModel 保存时兜底规范化 | ✓ 防绕过（粘贴、扫描预填等路径） |
| 注入面 | 补全后的字符串只作为 OkHttp 请求 URL 使用；OkHttp 自身校验 URL 合法性，非法输入在连接时失败而非执行 | ✓ |
| 凭证 | 补全逻辑不触碰 token 字段；token 仍逐字符由用户输入，不做持久化明文之外的附加处理 | ✓ |

## 4. 修复的发现（v0.2 审查）

**低危（已修复）**：网关原 `/health` 未鉴权返回完整 `host.describe`，
包含 PC 的 **cwd 绝对路径、provider/model 名、会话数** —— 任何能访问 8742 端口的设备都可读取。

- 处置：`/health` 改为只返回 `{gateway:{name,version}, upstream:{reachable}}`；
  详细 describe 仅可通过**鉴权后的** `/api/host.describe` 获取（App 本来就走这条路径）。
- 新增 `/ident`：未鉴权，但只返回静态 `{gateway:{name,version}, scheme}`，专供扫描器识别，零敏感信息。

## 5. 评估后有意接受的取舍

| 取舍 | 理由 |
|---|---|
| `/ident`、`/health` 不做限流 | 响应为常数级静态 JSON（几十字节），CPU/内存开销可忽略；扫描器一次扫 /24 需数百请求，限流会误伤正常扫描。若未来暴露到公网，必须换成鉴权或限流。 |
| 默认只探测 8742 端口 | 与网关默认配置一致；自定义端口用户手动输入 IP:port。mDNS/多端口探测见 ROADMAP。 |
| 仅扫手机所在 /24 | 家庭网络通用；/16 全扫耗时过长且无意义（网关必须在同广播域/路由可达网段才有用）。 |
| 蜂窝网络直接拒绝扫描 | `TRANSPORT_WIFI` 校验：避免向运营商网段喷洒探测包。 |

## 6. 使用侧建议（写给用户）

- 网关 token 只在「连接」时通过 HTTP 明文传输（家庭 WiFi 内），扫描阶段从不出现。
- 若路由器开启 **AP 隔离**，扫描与连接都会失败——这是网络隔离策略在起作用，属预期行为。
- 公共 WiFi 下不要使用扫描/连接功能（token 可被抓包），或先给网关启用 TLS。
